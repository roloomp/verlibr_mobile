## Авторизация (пункт 1)

- `ui/viewmodels/AuthViewModel.kt`: единственный владелец состояния. Создаётся в `VerlibrNavigator`
  (на уровне активити). `AuthState`: Loading / Guest / LoggedIn(profile). Источник правды: `AuthService.sessionStatus`
  (Initializing, Authenticated, NotAuthenticated). Обновление токена приходит как Authenticated:
  профиль заново не грузим, если id тот же.
- Профиль после входа грузится с 3 попытками (строка в `profile` может появиться с задержкой). Если так и
  не нашлась: минимальный профиль, имя из email. Это маскирует отсутствие триггера на стороне Supabase.
- `AuthService`: `login` / `register` возвращают `Result<Unit>` с готовым русским текстом ошибки
  (неверный пароль, email занят, короткий пароль, нет сети). Подтверждение почты в Supabase выключено.
- `AuthDialogs.kt`: `AuthController` хранит только UI (показ диалогов, busy, текст ошибки).
  Ошибки показываются внутри диалога: снекбар под окном диалога не виден.
- Шапка: залогиненный видит своё имя простым текстом (без рамки), гость видит кнопку «Вход». Пока идёт
  Loading, кнопки нет (чтобы «Вход» не мигал).
- Выход: кнопка «Выйти из аккаунта» на экране профиля.
- Гость: профиль и избранное показывают `GuestHint` с кнопкой входа. На экране стиха лайк, избранное,
  оценка и лайк рецензии открывают диалог входа.

## Экран стихотворения (пункт 2)

- `data/network/PoemDetailService.kt`: стих, теги (колонки `tag_*`, пустые пропускаются), лайки, избранное,
  оценки, отправка оценки, лайк рецензии.
- `PoemViewModel`: состояния загрузки (Loading / Error / Content), оптимистичные лайк и избранное с откатом,
  события `message` (Toast) и `needLogin` (открыть вход). Экран вызывает `onUserChanged(userId)`: при входе
  или выходе флаги «лайкнул / в избранном / оценил» перечитываются.
- Критерии маппятся по именам колонок, не по индексу: в БД порядок rhyme, style, structure, individuality,
  atmosphere, в приложении (`ratingCriteria`) рифмы, структура, стиль, индивидуальность, атмосфера.
- Оценка и рецензия лежат в одной таблице `ratings` (`has_review`). Средние считаются на клиенте:
  «с рецензией» по рецензиям, «без рецензии» по всем оценкам (как было в mock-версии).
- Повторная оценка того же стиха блокируется проверкой на клиенте.

## Избранное и профиль (пункт 4)

- `PoemService.favorites` (страница избранного: сначала `favorites`, потом `poem_previews` по id)
  и `PoemService.previewsByIds`.
- `ProfileService.load`: одним проходом грузит мои рецензии, мои оценки без рецензии, понравившиеся рецензии,
  понравившиеся стихи, число избранного. Пагинация в профиле клиентская (pageSize = 5).
- `ProfileViewModel`: `load(profile)` при каждом открытии, старые данные остаются на экране, пока идёт
  обновление. `showSpinner` / `showError` только до первой успешной загрузки.
- Статистика: «Оценок поставлено» считает и рецензии, и оценки без рецензии (решение, с вебом не сверяли).
  «Лайков поставлено» = понравившиеся рецензии + стихи, «Лайков получено» = лайки на моих рецензиях.
- `distinct` по id в списках: в БД нет UNIQUE, одинаковые `key` в LazyColumn роняют приложение.
- `FavoriteScreen` принимает `userId`, `loading`, `onLoginClick`.

## Главная (пункт 3)

- `data/network/HomeService.kt`, `HomeViewModel`, `HomeScreen`.
- «Находки дня» = `poems.is_daily = true`, «Выбор редакции» = `poems.is_editors = true`; по 6 стихов,
  новые сверху (id по убыванию); превью берутся из `poem_previews`.
- «Лучшие авторы»: допущение, правило с веба неизвестно. Сумма лайков всех стихов автора, при равенстве
  больше стихов, затем по имени; берётся 6. Считается на клиенте по двум запросам (poems: id, author_id;
  poem_previews: id, likes_count). Это упрётся в лимит PostgREST в 1000 строк, если стихов станет больше:
  тогда нужна вьюха или RPC на стороне Supabase.
- Годы автора: `birth_year - death_year`, при отсутствии смерти «н.д.», при отсутствии рождения «?».
- Экран перезагружает данные при каждом открытии (`LaunchedEffect(Unit)`), секции без данных скрыты,
  при первой загрузке спиннер, при ошибке «Повторить».
- Аватары авторов пока заглушки (круг Taupe).

## Экран автора (пункт 6)

- `data/network/AuthorService.kt`: `getAuthor(id)` (имя, годы, био из `authors`) и `poems(authorId, page, pageSize)`
  (стихи с `poems.author_id`, по алфавиту названия, превью из `poem_previews`).
- `AuthorViewModel` наследует `PagedPoemsViewModel`, id берёт из `SavedStateHandle["id"]`; данные автора
  грузятся отдельно (`author`, `authorLoading`, `authorError`, `loadAuthor()`).
- `AuthorScreen` = `PoemListScreen` с новым необязательным параметром `header`: `AuthorHeader` показывается
  первым элементом списка (аватар-заглушка, имя, годы, био, заголовок «Стихи»), под ним обычные карточки
  стихов и закреплённая пагинация. Переход из «Лучших авторов» на главной ведёт сюда (`author/{id}`).
- Аватар автора пока заглушка (круг Taupe и первая буква): `authors.avatar` не используется.
- Стихи автора сортируются по названию; по лайкам не сортируем, потому что `poem_previews` не содержит author_id.

## Списки стихов (Горячее, Избранное)

- `PagedPoemsViewModel`: `load(page, pageSize)` в наследнике, состояния loading / error.
- Пагинация вынесена из `LazyColumn` в `PoemListScreen` и закреплена внизу над нижней панелью, чтобы «1»
  не прыгал под пустым блоком или спиннером. На экране ошибки пагинации нет.
- «Горячее» = лайки за 30 дней (решение Романа): сортировка likes_month, likes_count, id.

## Supabase: что известно

- Таблицы: authors, poems, ratings, favorites, likes, review_likes, profile. Представление `poem_previews`
  (стих + likes_count, likes_month, reviews_count; создавалось в SQL Editor, файла в проекте нет).
- В схеме нет UNIQUE на (user_id, poem_id), (user_id, review_id) и нет CHECK на баллы. `user_id` без
  default `auth.uid()`: клиент шлёт его сам. Дубли отсекаются только проверкой на клиенте (гонка возможна).
- RLS нужно проверить (в коде не проверить): публичное чтение `profile` (имя автора рецензии), `ratings`,
  `likes`, `review_likes`; запись и удаление своих строк `auth.uid() = user_id`.
- Версии: supabase-kt 3.2.6 (BOM), Kotlin 2.2.10, плагин kotlinx-serialization подключён.
- Лимит PostgREST: 1000 строк на запрос (рецензии и их лайки на одном стихе, топ авторов).

## Отложено

1. Поиск: перенести фильтры в запрос к `poems` (название, автор, теги `tag_*`, год), серверная пагинация.
2. Аватар и баннер из `profile.avatar` / `profile.banner` и аватар автора из `authors.avatar`: нужна библиотека
   загрузки изображений (Coil в зависимостях нет) и Storage. Редактирование профиля (имя, био).
3. У `Review` нет ссылки на стих: в профиле рецензия без названия стиха и без перехода на него.
   Добавить `poemId` и название в модель.
4. В «Понравилось» нельзя снять лайк (карточки read-only). Если нужно, передать `onLike`.
5. Рейтинги на карточках списков пока не показываются, только лайки и число рецензий.

## Грабли

- Файлы с CRLF, при правках сохранять.
- Приватные top-level классы с одинаковым именем в одном пакете дают redeclaration (JVM-имя одно):
  в сервисах у DTO уникальные префиксы (Home*, Profile*, Favorite*).
- У свойства с `private set` Kotlin сам создаёт `setИмя`: свои функции так не называть
  (поймали на `AuthController.setBusy`, теперь `changeBusy` / `changeError`).
- `LazyColumn` падает на повторяющихся `key`: списки из БД без UNIQUE делать `distinct`.
